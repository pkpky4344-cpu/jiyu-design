# 병의원 리드 큐레이션 챗봇 — 설계 문서

## 배경 및 목적

jiyu design은 홈페이지를 통해 상업 공간, 특히 **병의원(치과/한의원/피부과·성형외과/일반의원 등) 인테리어 공사 계약**을 늘리는 것을 목표로 한다. 병의원 인테리어는 의사결정자(원장/사무장)가 시간이 부족하고 규제·일정 리스크에 민감한 B2B 구매 여정이며, 첫 방문에서 "이 업체가 병의원 인테리어를 잘 아는가"를 판단한다.

기존 `/consult` 상담 신청 폼은 범용 폼이라 병의원 특화 문의를 사전에 걸러내지 못한다. 이번 기능은 홈페이지에 뜨는 채팅형 위젯으로, 방문자를 짧은 선택형 문진으로 안내하고, 관련 시공 사례를 보여준 뒤, 리드(잠재고객) 정보를 수집한다. 자유 대화형 AI 챗봇이 아니라 **구조화된 문진 + 사례 노출 + 리드 수집** 흐름이며, 가격·법규 등에 대한 확답은 하지 않는다(리스크 회피).

기존 상담 신청 폼과는 **완전히 분리된 리드 파이프라인**으로 구현하여, 두 채널의 유입/전환을 비교하고 개선점을 파악할 수 있게 한다.

## 대화 흐름

1. **진입 질문**: "안녕하세요, jiyu design입니다. 병원·의원 인테리어 상담이신가요?" — 버튼(예/아니오)
   - 아니오 선택 시: 기존 `/consult` 페이지로 안내하고 챗봇 흐름 종료
2. **병원 종류**: 치과 / 한의원 / 피부과·성형외과 / 일반의원 / 기타 (버튼)
   - 답변 직후 **관련 시공 사례 노출** (아래 "사례 매칭 로직" 참조) — 병원 종류를 확인한 시점에 바로 신뢰를 형성하는 것이 효과적이라는 구현 리뷰 의견을 반영해, 평수 확인 이후가 아니라 이 단계 직후로 배치함
3. **진행 단계**: 신규개원 / 이전 / 리모델링 / 부분공사 (버튼)
4. **평수**: 20평 이하 / 20~40평 / 40평 이상 (버튼)
5. **희망 시기**: 1개월 이내 / 3개월 이내 / 6개월 이내 / 미정 (버튼)
6. **추가 요청사항** (자유 텍스트, 선택 입력) + **이름 / 연락처** + **개인정보 수집·이용 동의(필수 체크박스)** → 제출

버튼 선택이 기본이며, 자유 텍스트 입력은 7단계 추가 요청사항에서만 사용한다 (과도한 자유 대화형 UX를 지양).

## 사례 매칭 로직 (3단계 대체)

`lib/data.ts`의 `getPortfolioProjects()`를 2번 답변(병원 종류)과 매칭한다.

1. **정확히 일치**: 해당 병원 종류 카테고리의 실제 시공 사례가 있으면 그대로 노출
2. **부분 대체**: 해당 병원 종류 사례는 없지만 다른 상업공간 사례가 있으면, "아직 이 진료과목 전용 사례는 준비 중이지만, 저희가 진행한 상업공간 시공은 이런 느낌입니다"처럼 톤을 낮춰 솔직하게 안내 후 노출 (병원 사례로 오인시키지 않음)
3. **대체 불가**: 관련 사례가 전혀 없으면 사례 카드 단계를 건너뛰고 "정확한 시공 사례는 상담 시 실제 사진으로 안내드리겠습니다" 문구만 표시 후 다음 단계로 진행

현재(2026-09-08 기준) 포트폴리오에 병의원 카테고리 사례가 없어 3번 경로를 타게 되며, 사용자가 9월 11일까지 병의원 시공 사진을 전달하기로 함 — 전달되면 `lib/data.ts`에 병의원 카테고리 항목을 추가해 1번 경로가 동작하도록 한다.

`lib/db.ts`에 함수 추가 (기존 `client`/`ensureSchema` 패턴 재사용, 별도 DB 연결 불필요):
- `createChatbotLead(lead)` — INSERT
- `getChatbotLeads()` — 목록 조회 (최신순)
- `updateChatbotLeadStatus(id, status)` — 상태 변경

## API

기존 `lib/admin-auth.ts`의 `isAdminAuthorized()` 재사용.

- `POST /api/chatbot/lead` — 공개 엔드포인트. zod로 hospital_type/stage/size_range/timing/name/phone 필수 검증 (`/api/consult`와 동일 패턴), `createChatbotLead()` 호출
- `GET /api/admin/chatbot-leads` — 관리자 인증 필요, `getChatbotLeads()` 반환
- `PATCH /api/admin/chatbot-leads/[id]` — 관리자 인증 필요, `{status}` body로 상태 변경 (기존 `/api/admin/customers/[id]` PATCH와 동일 패턴)

## 프론트엔드

### 위젯 컴포넌트

`components/chatbot-widget.tsx` (신규, `'use client'`), `app/layout.tsx`에서 `<Header/>`/`<Footer/>`와 함께 최상위에 렌더링해 모든 페이지 우측 하단에 뜨도록 함.

**접힌 상태**: 우측 하단 고정 원형 버튼(56px, `bg-[#2a241f]`), 옆에 "인테리어 상담 도와드릴까요?" 말풍선 라벨. 아이콘은 얇은 라인 채팅 아이콘(라이브러리 아이콘 없이 인라인 SVG, 기존 lucide 아이콘과 동일한 stroke 스타일).

**펼친 상태**: 380px 폭 패널, `rounded-[28px]`, `bg-[#f9f5f1]`, `border border-[#2a241f]/10`, 부드러운 그림자 (`shadow-soft`류). 헤더에 `jiyu.` 워드마크 + "인테리어 상담" 라벨 + 닫기 버튼. 상단 진행률 바(5단계 중 현재 위치). 대화 영역은 봇 메시지(흰 배경, 좌측 정렬)/사용자 선택(차콜 배경, 우측 정렬) 말풍선. 활성 질문의 선택지는 `rounded-full` 필 버튼(사이트 기존 버튼 스타일 재사용). 사례 카드는 `panel` 클래스와 동일한 톤의 축소 카드.

디자인 시안: [Claude Design 목업](https://claude.ai/code/artifact/d8cd6d34-2440-4ba5-80d7-a8bd77f7d421) 참고 (승인됨).

색상/타이포는 `tailwind.config.ts`의 기존 토큰(`charcoal #2a241f`, `bronze #9d7a5f`, `sand #e8dac7`, `mocha #54463e`)과 사이트 배경색(`#f9f5f1`)을 그대로 재사용하며 새 색상을 추가하지 않는다.

### 관리자 페이지

`/admin`에 탭 2개 추가: **상담 신청** / **챗봇 리드**. 각 탭은 기존과 동일한 형태(상태 요약 카드 3개 + 목록 테이블, 상태 드롭다운으로 즉시 저장)를 유지하되 독립된 데이터 소스(`/api/admin/customers` vs `/api/admin/chatbot-leads`)를 사용한다. 두 채널 합산 비교 통계는 이번 범위에 포함하지 않음 (필요 시 후속 작업).
